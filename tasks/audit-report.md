# Отчёт: закрытие 3 «белых пятен» инженерного аудита (Phase 14)

## Вопрос 1: Как удалять импортированные турниры — БЫЛА недоработка, исправлено

Сценарий «загрузил чужой/не тот архив, нажал Сохранить» закрыт сквозным механизмом удаления:

| Слой | Код | Что | Почему |
|---|---|---|---|
| Сервис | `services/tournaments.ts` → `deleteImportedTournament(roomId, tournamentId)` | DELETE по `(room_id, tournament_id)` + `recomputeRoomBalances`; 400 на не-целое id, 404 на отсутствующую строку | Удаление идёт ключом импорта (не зависит от даты); рекомпьют снимает авто-интерполяцию дня, потерявшего единственный турнир |
| Роут | `routes/tournaments.ts` → `POST /api/tournaments/delete-import` (`{roomId, tournamentId}` → `{ok:true}`) | Тонкий лего по сервису | Тонкие роуты — проектное правило |
| Клиент API | `client/lib/api.ts` → `tournaments.deleteImport(roomId, tournamentId)` | POST JSON на /delete-import | Единый `request`-слой |
| UI | `TournamentPopup.tsx` | Сохранённые импорты, показанные read-only, получают кнопку ✕ (колонка «Удалить»); для строк уже в БД — `deleteImport` + `onChanged()`, для свежеразобранных — локальное удаление; при ошибке строка возвращается | Пользователь может вычистить ошибочный импорт прямо из попапа; попап остаётся открытым, сессии/балансы обновляются |

Дополнительно исправлен скрытый баг: ранее таблица импортов рендерилась только внутри блока `importStats` (после свежего разбора), поэтому **уже сохранённые** импорты при переоткрытии попапа были невидимы. Теперь таблица рендерится при `imports.length > 0`, стейт `savedImportIds` различает «в БД» и «ещё не сохранено», «Убрать импорт» остался только для несохранённого разбора.

## Вопрос 2: Временные зоны — правок не требовалось

`parseGgFile` (ggimport.ts): `DATE_RE = /^Tournament started\s+(\d{4})\/(\d{2})\/(\d{2})/`, дата = `${m[1]}-${m[2]}-${m[3]}` — строгая подстрока из текста, без `new Date()` на таймстампе `16:15:00`. `isValidDayKey` — валидация локальным «полуночным» round-trip → в любом TZ день не сдвигается.
