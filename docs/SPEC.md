# Spec: Poker CRM

## Objective

Личный веб-кабинет «Покерная CRM» для одного пользователя, запускается локально. Назначение — покерная бухгалтерия: балансы румов, сессии, румы, депозиты/выводы/переводы, турниры и долгосрочная статистика (график профита как SharkScope, календарь активности).

Успех: пользователь заполнил балансы по румам → увидел профит по сессии (по румам и суммарно); заполнил турниры → график профита, где каждый турнир влияет; расхождения >5% между турнирами и дельтой баланса подсвечиваются с вариантами решения.

## Tech Stack

- TypeScript везде.
- Client: React 18 + Vite + Tailwind CSS. Тёмная минималистичная тема (см. скиллы `frontend-design`, `emil-design-eng` при реализации dashboard).
- Server: Node.js + Fastify.
- DB: SQLite (better-sqlite3) — быстрый, синхронный доступ, локально.
- Парсинг PokerDom: Playwright + headless Chromium (запускается при старте сервера, невидим для пользователя, страница может открываться долго → таймауты и ожидания).
- Курсы EUR/USD: open.er-api.com (free, без API key).
- Графики: Recharts (линия профита), календарь активности — кастомный.

## Commands

- Dev: `npm run dev` (Vite + сервер параллельно, горячая перезагрузка)
- Build: `npm run build` (client build + сборка сервера)
- Start: `npm start` (production-запуск, собранный client + сервер)
- Test: `npm test` (vitest, unit)
- Lint: `npm run lint`
- Backup: `npm run backup` → дамп `data/backups/poker-crm-<date>.sqlite`

## Code Style

- Строгий TypeScript (`strict: true`).
- Zoneless отображение сумм: деньги храним как DECIMAL (целое число областей — код валют + целые копейки) или числа с округлением в 2 знака в минимальных юнитах; никаких float для денег. Денормализация в USD при записи не хранится — считается по курсу на дату.
- Именование: `camelCase` для функций/переменных, `PascalCase` компоненты, kebab-case файлы.
- Пример (профит за сессию):

```ts
// profit = delta_balance - (in - out)  // все суммы в минимальных единицах валюты
function sessionRoomProfit(
  oldBalance: Money, newBalance: Money,
  flowIn: Money, flowOut: Money
): Money {
  return newBalance.minus(oldBalance).minus(flowIn.minus(flowOut))
}
```

## Testing Strategy

- vitest. Юнит-тесты обязательны для всей денежной математики: расчёт профита сессии (по руму/суммарно), конвертация с фиксацией курса на дату, расхождение >5% + вариант «списать на казино», поведение пустых строк турниров.
- Интеграционные тесты API (без реального браузера; scraper мокается).
- E2E (опционально, позже) — Playwright.

## Boundaries

- **Always:** тесты перед коммитом; денежная математика покрыта юнит-тестами; валидация входных данных; даты в едином часовом поясе; курс фиксируется на дату и не пересчитывает прошлое.
- **Display rule (важно):** независимо от валюты кассы/турниров/румов, **все** суммы конвертируются и отображаются в USD — банкролл, статистика, все графики. Конвертация: direct rate → inverted → цепочка через USD; курс дня, fallback на последний известный курс, если на этот день курса нет.
- **Ask first:** изменение схемы БД; добавление зависимостей; изменение подхода к парсингу PokerDom; смена API курсов.
- **Never:** коммитить секреты/ключи; хардкодить курс; брать «первую попавшуюся цифру» из страницы PokerDom; молча игнорировать расхождение >5%.

## Success Criteria

- Заполнил балансы по N румам за день → сессия с профитом по каждому руму и суммарно (корректно с учётом депозитов/выводов/переводов).
- Смена баланса → рядом появляется «Заполнить турниры» → поп-ап со строками «байин + результат», пустая строка не считается, новая строку добавляется автоматически.
- Каждый турнир влияет на график (профит = результат − байин; байин без выигрыша = −байин).
- Расхождение >5% между турнирами и дельтой баланса → предупреждение + варианты: поправить баланс / поправить турниры / списать на казино.
- Курс PokerDom парсится с сайта через headless-Chromium (ждём загрузку, берём нужный курс, не первую цифру). Курс фиксируется на день, прошлые дни не пересчитываются.
- Календарь активности: <15 турниров красный, 15–20 оранжевый, >20 зелёный.
- Тёмный минималистичный современный UI.

## Парсинг курса PokerDom (USD → RUB)

- URL: `https://wer7pokerdom.com/poker` (headless Chromium через Playwright).
- На странице — таблица курсов валют вида:
  ```
  KZT   0,1944 ₽
  AZN  52,5840 ₽
  USD  89,3936 ₽
  UZS  0,0076 ₽
  EUR 103,9569 ₽
  ```
- Брать **только строку «USD»**: находить по метке валюты, а не «первое попавшееся число». Нормализовать десятичный разделитель (запятая → точка).
- Валидация: значение должно быть правдоподобным (диапазон, напр. 1–500); иначе — не сохранять, повторить попытку. Исключить случайный/неверный захват.
- Страница может открываться не сразу → щедрые таймауты ожидания, ретраи.

## Обновление курса (стартовый сценарий сервера)

1. Сервер стартует.
2. Проверка в БД времени последнего успешного обновления курса.
3. Если курс отсутствует ИЛИ старше 12 часов → запуск Playwright (headless, невидимый для пользователя).
4. Открыть `wer7pokerdom.com/poker`, дождаться загрузки таблицы (ожидаемая длительность — ретраи/таймауты).
5. Спарсить строку USD (см. выше), провалидировать.
6. Сохранить в `exchange_rates` (дата, USD→RUB). Старые даты не пересчитываются.
7. При успехе — лог; при провале после N попыток — лог-предупреждение, сервер продолжает работу на последнем известном курсе (отметка «устарел»).
   - **Уведомление при провале:** факт неудачи сохраняется в БД и показывается на сайте как персистентный баннер-алерт, который **не исчезает при перезагрузке страницы** и пропадает только по явному нажатию пользователя (или автоматически при успешном обновлении курса). Цель — пользователь наверняка обратит внимание и разберётся с проблемой.
8. EUR→USD: open.er-api.com (без ключа), та же заморозка по дате.
